# 2026-11-05: First detection, failed Windows logons (4625)

**Did:** Restarted Wazuh (Docker, single-node, on an Arch VM in VMware). Installed the Wazuh agent
on my Windows laptop (`vivobook`). Locked the screen and entered wrong credentials on purpose.
Wazuh caught them: **4 × Event ID 4625**, rule **60122** "Logon Failure - Unknown user or bad
password", level 5.

**What the event showed:**

| Field | Value | Meaning |
|---|---|---|
| `eventID` | 4625 | Failed logon |
| `logonType` | 2 | Interactive: someone at the keyboard |
| `ipAddress` | 127.0.0.1 | The machine itself, not a remote host |
| `logonProcessName` | User32 | The Windows login screen |
| `status` | 0xc000006d | Logon failed (general) |
| `subStatus` | 0xc0000380 | The specific reason. Looks like a wrong Windows Hello PIN; still checking |
| `targetUserSid` | S-1-0-0 | Null SID: Windows didn't tie the attempt to an account |

**Broke:** I typed 8 wrong attempts but only 4 were logged. Most likely the PIN screen doesn't
log every attempt the same way a password does. To test with a password next time.

**Learned:** How a real remote attack would look different from my local test:

| | My test | RDP brute force from the internet |
|---|---|---|
| `logonType` | 2 (keyboard) | 10 (RDP) |
| `ipAddress` | 127.0.0.1 | The attacker's public IP |
| Pattern | 4 failures | Many failures fast, then maybe one **4624** = they got in |

The single 4624 after a run of 4625s is the real emergency: the attacker is inside. First
response: disable the account, block the source IP, then check what happened after the logon.

**Next:** Windows VM in the lab → real brute force over RDP with Hydra → make the Wazuh
multiple-failures rule fire.
